# 加密备份与跨服务器恢复

左下角 **备份与恢复** 是独立功能，与“更新前回滚备份”分开。支持完整三合一安装；外部 AstrBot 加装模式暂不支持，以免漏掉另一个目录或 Docker 卷中的旧数据。

## 导出

1. 结束正在进行的聊天和任务，在统一入口打开 **备份与恢复 → 导出备份**。
2. 设置至少 12 个字符的备份密码，也可生成随机密码。妥善另外保存密码；项目没有密码找回接口。
3. 选择 **保存在服务器** 或 **下载到电脑**，再开始导出。
4. 执行器暂停 AstrBot、QwenPaw、NapCat，确认停止后复制一致快照，然后恢复此前运行的服务，再压缩加密。选择下载时，在完成后点击下载链接。

导出的是单个 `.aqbackup` 文件，内部为 ZIP，外层使用 Scrypt 派生密钥和分块 AES-256-GCM 认证加密。它不是普通 ZIP 密码文件，不能通过解压软件直接打开。密码不写入日志、浏览器存储或磁盘请求明文。

备份包含 `state/` 中的聊天、插件、模型配置、个人记忆、工作区、任务、附件及 QQ 登录资料，另含私有 `.env`、安装标记和逐文件校验清单。不包含 Docker 镜像、源码、更新缓存及备份文件自身。服务器保留的加密文件位于 `runtime/backups/private/archives/`；下载页通过单独的加密副本提供文件。下载一份到服务器以外的位置，才能应对整台 VPS 丢失。

## WebDAV 每日自动备份

0.8.0-alpha 起，**备份与恢复 → 自动备份** 可以每天生成加密包并上传到多个网盘。功能默认关闭，网盘由用户自备；不需要在服务器安装网盘客户端。支持 1–10 个 HTTPS WebDAV 目标，账号需要对应目录的创建、读写、重命名和删除权限。必须填写网盘提供的 WebDAV 接口地址，普通网盘分享链接不能作为接口使用。

1. 用 `start.cmd` 或 `bash deploy/start.sh` 启动完整三合一安装，再打开 **自动备份**。
2. 设置每日时间、固定 UTC 偏移和保留份数。默认是每天 03:00、UTC+08:00、保留 7 份；可设置保留 1–100 份。固定偏移不会自动跟随夏令时。
3. 设置至少 12 个字符的**自动备份密码**并再次输入，另外保存在密码管理器等服务器以外的位置。此密码用于解密备份，和网盘的应用密码不同。修改密码只影响新包，旧包仍需要生成它时使用的密码。
4. 点 **添加网盘**，填写名称、完整 HTTPS WebDAV 地址、账号及应用密码。可以把网盘自己的子目录包含在地址中。按需添加其他网盘，分别勾选启用。
5. 点 **保存设置**，然后分别点 **测试连接**。连接测试会写入、读取并删除一个随机命名的小文件；成功不代表网盘能容纳任意大小的完整备份，还需检查空间、单文件上限和流量限制。
6. 先点 **立即备份到网盘**，查看每个网盘的上传结果。确认可用后开启 **每日自动备份** 并保存，页面会显示下次运行时间。关闭每日计划仍可手动上传。

坚果云等服务需要在其**第三方应用管理**中生成专用应用密码，普通网站登录密码不能代替。0.8.1-alpha 修复部分服务 HEAD 响应将文件大小返回为 0 的兼容问题，使用 WebDAV 文件属性核对上传大小，仍会拒绝真实不完整的文件。

这是每日**全量上传**，保留份数控制已有文件数量，不会减少每次上传的流量。配置时请按单个备份包大小和网盘的月上传额度估算；流量受限时可以关闭每日计划，改用手动备份或其他已配置网盘。

每次只生成一个加密包，再分别上传到所有启用的网盘。生成快照时三组件会短暂停止，之后恢复服务再上传；一个网盘失败不影响继续处理其他网盘。临时网络错误最多尝试 3 次，账号、权限、空间不足等错误不会反复请求。**重试失败网盘**只重传最新一轮中失败的目标，使用已存在的本机加密包，不重新停止服务生成快照；需保留原包，目标地址或账号改变后不能把原失败轮次当作同一目标重试。

浏览器可以关闭，但宿主备份执行器、Docker 和三合一服务需要继续运行。计划写在宿主机；错过数天后，执行器恢复时最多补做一次，不会连续生成每天一份。更新、备份、恢复使用同一操作锁；正在检查或执行恢复时不会启动定时备份。主机休眠、关机或执行器退出期间无法备份。

### 保存、加密和清理范围

- 网盘只收到 `.aqbackup` 密文文件，保存在所填地址下的 `astrbot-qwenpaw/<本安装随机标识>/` 中。每个新安装都有自己的目录。
- 为了无人值守运行，网盘应用密码与自动备份密码会用独立本机密钥加密保存在宿主私有目录 `runtime/backups/private/webdav/`。它们不写入公开状态、浏览器存储或日志，网关容器不能读取该私有目录；能够控制宿主机及密钥的人仍可能访问这些凭据。
- 这些自动备份设置、凭据及本机加密密钥**不包含在迁移包中**。迁移到全新 VPS 后需重新配置网盘，并自行提供原备份的解密密码。开始导入恢复前会暂停目标安装的定时计划；恢复后检查设置，再手动启用。
- 每个网盘在新包成功上传后，才按保留份数清理**本安装、该目标中已记录上传成功的旧文件**。不会遍历清空网盘，也不删除其他安装或用户自己放进去的文件。移除目标或更换地址、账号不会自动清理原网盘；原文件仍由用户自行管理。
- 本机把本功能生成的包按“全部目标上传成功”和“尚未全部上传成功”分别保留最近 N 份，因此正常清理后最多保留 **2N 份**；每个网盘独立保留最近 N 份。旧失败包也会按此规则轮换，以免网盘长期故障导致本机持续积累。仅在新加密包已成功导出并通过本机完整性校验后，才会清理旧包；新包生成或校验失败时保留旧副本。
- 普通 **导出备份** 产生的文件和恢复回退快照不属于上述轮换范围。清理失败时保留旧文件并在后续运行重试，实际份数可能暂时超过设定。页面显示最近 20 轮运行记录，旧记录可能对应已轮换的包；仅最新一轮失败上传可直接重试。保留份数不等于磁盘总占用上限，请定期检查空间。

当前验证覆盖标准 HTTPS/WebDAV 协议、模拟错误响应、多目标调度，以及坚果云 HEAD 返回 0 的兼容回归。不同服务商对单文件大小、流量、WebDAV 操作和限流的实现可能不同，配置后应完成一次真实导出、下载和恢复演练。

## 在新 VPS 恢复

1. 在新 VPS 解压完整项目，使用与备份相同的三组件版本，安装 Docker Compose 与 Python 3.10+，运行 `bash deploy/start.sh`。Windows 使用 `start.cmd`。首次缺少加密库时，启动器只在项目自己的环境中安装固定依赖，需要能连接 PyPI；部分 Linux 发行版需预装 `python3-venv`。
2. VPS 的入口仅监听回环地址。通过 SSH 转发后，从本机浏览器访问 `http://localhost:18080/`：

   ```sh
   ssh -L 18080:127.0.0.1:18080 your-vps
   ```

   保持 SSH 连接；本机同一端口已有旧安装时先停止它，或在另一台电脑连接。不要把此入口直接开放到公网。

3. 选择 **导入恢复**，上传 `.aqbackup` 并输入密码。此时只解密和检查，不替换当前数据。
4. 检查组件版本、文件数量、数据大小和路径检查结果。停止旧 VPS，避免两个机器人和定时任务同时运行。勾选确认旧服务器停止；目标已有数据时，另行确认替换。
5. 点击恢复。执行器先保存目标当前数据及镜像标识，再恢复备份并重新创建相关容器；重写安装目录、源码目录、Compose 项目和内部服务地址，保留目标代理配置。
6. 等待网页重新连接并显示检查通过，随后验证聊天、记忆、插件、任务与文件。QQ／微信可能需要重新登录，旧服务器确认不再需要后再下线。

原备份的通信密钥会随数据恢复，以保留个人助手的归属与签名。不要在恢复后直接用新生成的密钥替换它们。模型 API、QQ 会话等信息随备份迁移，务必把备份视为私人资料。

## 中断与回退

更新和备份恢复共享操作锁，同一时间只运行一个修改任务。恢复服务或桥接检查失败时，会尝试恢复本次操作前的数据、私有配置与旧镜像。异常关机后，再次运行启动脚本会先处理未完成事务。需要人工介入时会禁止后续操作；保留 `runtime/backups/private/`，查看其中固定错误码记录，不要反复清空目录或重新导入。

检查成功后的解密暂存仅存于宿主机私有目录，恢复计划一小时过期，空闲服务会清理过期暂存。密码错误或文件损坏时清理失败的暂存。浏览器和网关只接触加密文件、签名状态与受限请求，网关没有 Docker socket，也不能读取私有备份目录。

## 当前限制

- 备份密文最大 8 GiB、解压内容最大 32 GiB、最多 100,000 个文件，单文件最大 8 GiB。需要额外空间保存快照、解密暂存和回退数据；空间不足会停止操作。
- 三组件版本和 Docker 架构必须匹配，暂不执行跨版本数据库升级、降级或跨 CPU 架构转换。整合层版本可以不同，但必须支持备份格式 1。
- 默认全新 Linux／Windows 完整安装受支持。旧 `deploy/setup.sh` 全新安装可用 `bash deploy/start.sh --data-dir /opt/bot-combined` 接入统一入口；必须属于当前源码目录且挂载符合标准布局。已有 AstrBot 加装、额外的未识别挂载、链接和特殊文件会拒绝处理。
- 仅自动修正项目生成的部署路径与内部地址。用户在插件、脚本、外部数据库或任务中手填的绝对路径、域名、网盘凭据需要恢复后自行检查，不会盲目替换聊天或文件正文。
- 服务暂停期间对话和执行中的任务会中断，平台不保证补发；这不是零停机迁移。原有定时任务随数据恢复，旧服务器必须停止。
- 已支持上述 WebDAV 每日全量备份和限定范围的保留轮换；尚无 S3 原生接入、增量备份或直接从网盘选择恢复。恢复时先从网盘下载 `.aqbackup`，再通过 **导入恢复** 上传。普通手动导出与回退快照仍需自行维护空间。
- Docker 自动重启容器不代表宿主备份执行器已经启动。主机重启后运行启动脚本；长期 VPS 可由管理员将 `bash deploy/start.sh` 接入自己的服务管理。

源码只下载即可运行；网页自动更新仍需要完整 Release 安装清单。无论部署方式如何，都应使用模拟数据先完成一次导出与恢复演练。
