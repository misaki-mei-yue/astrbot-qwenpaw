# 更新与恢复

网页更新适用于 `deploy/compose.bundle.yaml` 的本机统一入口部署。Windows 用户需要通过新版 `start.cmd` 启动；它会启动一个隐藏的 Python 更新执行器。执行器使用固定的本机 Docker context 和当前安装目录，不处理其他项目。停止时运行 `stop.cmd`；更新正在执行时会拒绝停止，请先等任务结束。

## 使用

1. 左下角打开 **检查更新**，再点击窗口内的 **检查更新**。
2. 查看当前版本、目标版本、三个组件版本和发布说明。
3. 点击 **备份并更新** 开始安装。升级期间请保持电脑与 Docker 运行。
4. 更新完成后刷新界面；服务重启时页面会自动重新连接。

检查不会自行安装。仅检查本项目固定 GitHub 仓库的 Release，并校验压缩包、SHA256SUMS、发布文件摘要（存在时）、逐文件清单与版本元数据。校验和不是独立的发布者数字签名：发布账号与 HTTPS 仍属于信任边界。测试版安装允许后续测试版更新；稳定版默认只选择稳定版。

“兼容更新”指本项目维护者固定并验证的组件组合，不能保证三个上游各自最新版本立即兼容。不会自动拉取任意 `latest`。本地源码构建 QwenPaw 的模式、被修改的已管理源文件、没有安装清单的源码检出或未完成的恢复，会阻止应用更新。

## 数据与中断

下载、备份、事务记录和详细诊断都在安装目录的 `runtime/updates/private`；网关无法访问这个私有目录。更新只给网关一个经过签名的文件通信目录，没有给它 Docker socket 或宿主机命令接口。请求限定为检查或安装已验证的候选版本。

更新前请结束进行中的对话和任务，并暂停 QwenPaw 中的定时任务；执行器发现仍启用的定时任务会拒绝更新，但不能自动判定所有正在进行的工作是否完成。新版启动后又回滚，会使任务完成标记随数据恢复，因此请安排在空闲时段更新。

更新先准备镜像，再停止服务，确认停止后复制运行数据与配置，并保存旧代码和旧镜像标识。确认新服务与桥接检查通过后才结束事务。失败会尝试停止新服务、恢复旧程序及备份数据，再使用原镜像启动；不会仅恢复镜像而留下已迁移的数据。如果停止或恢复失败，会暂停后续更新，保留现场和备份以便恢复。

升级会短暂中断微信、QQ 对话与后台任务。没有双实例切换，也不保证服务停止期间消息一定补发。页面重新连接不等于聊天完全不中断。异常关机后再次启动更新执行器会先检查未完成事务。

备份包含密钥、聊天和记忆，应按私人数据保护。执行器不会自动删除旧备份或 Docker 镜像；磁盘不足时会拒绝开始。可在确认新版稳定并另外备份后，手动清理不再需要的旧更新备份。不要把 `runtime` 上传到 GitHub 或发送给别人。

## 旧版首次升级

0.5.0-alpha 没有更新执行器，需下载新版完整包，将公开源码更新到原安装目录，保留 `runtime` 后运行新版 `start.cmd`。先另行备份原目录；不要用新建的空运行目录代替旧目录。后续支持的发布版本即可从网页检查并更新。

## Linux

0.7.0-alpha 起，完整安装可运行根目录 `bash deploy/start.sh`，由启动器准备配置并启动更新／备份执行器和统一入口，停止使用 `bash deploy/stop.sh`。跨服务器迁移使用独立的[备份与恢复](backups.md)，不使用更新事务目录代替迁移包。

传统 `compose.yaml` 和已有 AstrBot 加装流程仍使用原部署说明，暂不支持此网页更新。需要本机统一入口时，在完整源码目录中准备配置并使用 `compose.bundle.yaml`。用 Python 3.10+ 启动宿主执行器：

```sh
python scripts/run_bundle_updater.py --ensure --root "$PWD" --project YOUR_COMPOSE_PROJECT --context default
```

项目名必须与现有 Compose 部署一致，而且必须等于 `astrbot-qwenpaw-bundle-` 加安装源码绝对路径（全部转小写）的 UTF-8 SHA256 前 10 位。请先按这个名字创建 Compose 部署；更新器不会接管任意现有项目。仅接受本机 Unix socket，拒绝远程 context。配置、IPC 权限和本地目录必须满足检查。停止前用同样参数将 `--ensure` 改为 `--stop`。请先在测试环境验证自己的 Linux 文件权限与 Docker 安装方式。
