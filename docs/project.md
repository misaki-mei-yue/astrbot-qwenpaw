# 项目立项

项目名称：**asrtbot和qwenpaw的结合版**。仓库名称：`astrbot-qwenpaw`。

目标：在同一服务器组合 AstrBot 的微信 / QQ 和插件生态，以及 QwenPaw 的长期记忆、主动任务、文件与浏览器能力。通过独立插件集成，保留两边升级路径。

## 交付阶段

1. **桥接首版**：双向文本、可靠会话映射、原插件命令、显式授权的模型工具、主动回传、原会话审批、安装文档与协议测试。
2. **真实联调**：服务器运行固定版本，微信与 QQ 完成登录，验证当前使用的插件、真实模型与任务；记录资源用量、失败恢复和重启行为。
3. **媒体与持续任务**：共享目录中图片 / 文件 / 视频的安全转换，长任务进度与恢复，插件生成文件的统一出口。
4. **组合管理体验**：后台状态、任务列表、记忆查看与权限设置，减少在两个后台之间切换。

第一阶段是后续功能的基础。阶段二到四未完成前，不应宣称已经具备全部插件兼容性或完整生产能力。

当前进度：0.1.0 文本桥接已发布；0.2.0 补充媒体双向协议、会话文件目录和主动发送文件工具。媒体协议测试可以先于服务器联调进行，真实收发仍按下面清单验收。长任务状态体验与组合管理界面尚未完成。

## 服务器验收

- [ ] 微信和 QQ 同时接入；两边 ID 相同也不会混用会话。
- [ ] 普通文本只有一个回答，命令由原插件处理。
- [ ] 记忆在容器重启后可继续使用；历史数据库没有被自动合并。
- [ ] 文件操作只访问指定工作区，浏览器任务可实际完成。
- [ ] 放行的 AstrBot 工具能运行，未放行工具不能运行。
- [ ] 任务最终结果回到发起用户与会话。
- [ ] 需确认的操作显示具体目标；另一会话不能批准。
- [ ] 断线、平台重发、同一回调重试不会重复执行同一调用。
- [ ] QQ / 微信真实发送失败可在后台定位；“提交到适配器”没有被当作平台送达保证。
- [ ] 完整负载下记录内存、CPU、磁盘与任务耗时。

所有服务运行在服务器，调用在线模型服务。浏览器与多个运行时同时工作时，需要按实测升级内存；部署脚本不购买或变更云资源。
