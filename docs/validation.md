# 验证范围与复现

公开测试版 **0.5.0-alpha**。测试分成协议、原生运行时、浏览器和真实平台四层；下层通过不自动证明上层可用。这里不发布个人会话、账号或诊断历史。

## 常规回归

在独立开发环境中运行：

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

覆盖身份隔离、账号绑定、路由、工具权限、审批、持久化防重、媒体、网关、部署准备与 Windows 启动器边界。部分检查使用本机 HTTP 或接口替身，不登录平台、不调用付费模型。

Windows 的符号链接／POSIX 能力、未开启的真实 Chromium 检查或缺少可选依赖可能导致跳过。应记录 Python、系统、通过／失败／跳过数量与对应提交，不能将跳过视为通过。完整 CI 结果以[对应提交的 Actions](https://github.com/misaki-mei-yue/astrbot-qwenpaw/actions) 为准。

当前公开版专项已在匹配的 Linux 原生环境通过 **34 项工作区守卫检查与 8 项 DeepSeek 协议兼容检查**。它们使用合成数据，不证明真实模型的自动记忆质量或平台送达。全套回归应随发布提交重新运行，不引用个人环境历史统计替代。

## Compose 与脚本

Linux 中检查准备脚本语法：

```bash
bash -n deploy/setup.sh
bash -n deploy/upgrade_existing.sh
```

在空的专用测试目录准备配置后，用相应模式的 `docker compose ... config --quiet` 校验，见[部署说明](deployment.md)。准备脚本只写文件；Compose 解析成功也不表示容器已经运行。不要拿已有账号目录做准备脚本实验。

Windows 启动器的部分自动测试通过受控进程替身检查参数、失败即停、数据保留和项目范围。真实启动需另外确认 Docker 引擎、四服务及三套原生页面。

## 原生运行时检查

脚本提供可复现检查入口，需匹配的上游版本及完整依赖，常规轻量测试依赖不足以执行全部内容：

| 脚本 | 覆盖内容 | 不证明的内容 |
|---|---|---|
| `scripts/check_astrbot_runtime.py` | 真实 AstrBot 核心加载、消息流水线与工具执行器 | 真实 QQ／微信送达 |
| `scripts/check_personal_runtime.py` | 个人 Agent、原生配置、明确备注与索引隔离 | 自然对话的自动提炼质量 |
| `scripts/check_qwenpaw_runtime.py` | 文件、ReMe 检索、Cron 执行与重启留存 | 付费模型能力及日历到点送达 |
| `scripts/check_upstream_media.py` | 固定上游真实消息类型与媒体转换 | 完整容器启动、平台上传结果 |
| `scripts/check_qwenpaw_browser.py` | 真实浏览器 SDK 与工具进程读取／点击 | 模型规划能力、外部网站兼容 |

先运行各脚本的 `--help`。固定源码检查需要干净上游 checkout 或官方构件；测试专用数据根必须与正式运行目录分开。不得挂载真实模型密钥、QQ 登录资料、聊天工作区或宿主浏览器 profile。

记忆检索检查应等待原生文件 watcher 摄入，再调用原生 `memory_search`，验证新词出现、旧词移除及跨用户不可召回。不能用自行实现的替代搜索证明原生检索成功。

历史 fixture 报告如保留，只说明其中列出的固定环境和断言，不代表当前提交已重跑。报告不应包含私人路径、账号、聊天、浏览器资料或密钥。

## 真实浏览器

受管助手的真实 Chromium 用例需要显式开启：

```bash
ASTRBOT_BROWSER_REAL_TESTS=1 ASTRBOT_BROWSER_EXECUTABLE=/usr/bin/chromium python -m unittest discover -s tests -p test_personal_browser.py -v
```

在可写的独立测试环境执行；只读容器需将浏览器配置与缓存目录指向测试临时目录。页面可由同一容器的 loopback 测试服务提供，无需真实账号。应验证页面读取、点击、填写、不同助手 Cookie 隔离与私网重定向拒绝。

统一入口界面检查使用 `node scripts/check_bundle_ui.cjs`，另需 Playwright / Chromium 环境。页面替身应明确标注；替身显示成功不能当作三套上游后台已运行。

## 部署者的首次验收

用无敏感资料完成以下步骤，再增加并发或接入其他人：

1. 三套原生后台可访问，模型配置有效，桥接频道启用，未授权用户不能调用。
2. 在同一私聊连续发多条消息，确认上下文持续；重启后会话和明确备注保留。
3. 两个用户和群聊的记忆不串；跨平台绑定需要两端确认，已有独立空间不会被静默覆盖。
4. 普通 AstrBot 插件命令有效；工具允许列表为空时拒绝桥接调用，放行后仍保留原插件权限。
5. 发送一张小图片和一个小文件，再回传一个生成文件；超限、越界和重复回调按预期处理。
6. 运行一次浏览器任务和一条需审批的主动任务，确认审批目标、结果会话与实际送达。
7. 查看 CPU、内存、交换空间与磁盘变化，验证暂停、重启及网络失败时不会无提示重复执行动作。

真实模型会产生费用，平台测试可能发送消息，应由部署者明确执行。模型提供商、媒体理解、第三方插件、浏览器网站和硬件负载分别验收，不将“健康检查通过”作为全部功能证明。
